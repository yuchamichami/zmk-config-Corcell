# IQS9151 TPS43-outline A2：右側FPCでの初回評価

## 対象・固定ソース

独自A2基板（FR4 1mm、13Rx×12Tx、156交点）、1mmオーバーレイの初期設定。
Azoteq純正TPS43向けの調整済み設定ではありません。材質・接着層・軸・感度・消費電流は未検証です。
右側をUSB/BLEのcentral、左側をperipheralとする既存Corcell構成を維持します。
左は従来PAW3222ファームを使い、既存のsplit入力転送・処理を維持します。A2の左接続は今回の対象外です。

- ベース: dya-studio `8f1fc03514f7d1f2656f1db04b4541592b105ed2`
- ZMK: cormoran/main+dya（今回の確認対象 `e5c9b6915b56801193e359dd9bad4a167ce0d1b8`）
- Zephyr: v4.1.0+zmk-fixes+nrf-half-duplex-uart（確認対象 `7c6b4cc486ecb41a68d9c2b1def2bb3178fbb826`）
- IQS9151: https://github.com/yuchamichami/zmk-driver-iqs9151 @ `42fbda63f957a8f9f7e13fb2abfbdbde3d84fcf5`
- PAW3222: 既存の `fc946760e7f870e512be8fce7a26cc5c004a8663` を維持。

元のShiniNet版を二重に追加していません。現行Corcell manifestにはIQS9151プロジェクトがなかったため1件追加しました。
ドライバー本体や外部geometry.hへのパッチはありません。指定ドライバーの内蔵A2プロファイルを使います。
既存キーマップ・キー走査・エンコーダー設定は維持しています。新ドライバーモジュールが既定で有効にする未使用のbehavior/processorは明示的に無効にし、従来版への影響を抑えています。

## 配線とGPIO

以下は提供されたCorchibi V3 R PCBとA2 PCBの**設計データ上の照合**です。現物の実装・通電、FFC同面/異面接点と両端の向きは未確認です。番号が逆転していないことを通電前に確認してください。

| A2 J1 | A2信号 | ホストConector1 | XIAO/nRF | 用途 |
|---|---|---|---|---|
| 1 | RESET_EXT | NCS / JP1中央 | 未接続 | reset-gpiosを省略 |
| 2 | SCL | SCLK | P0.10 | I2C0 SCL |
| 3 | RDY | MOTION | P1.12 | active low、A2側4.7kΩプルアップ |
| 4 | SDA | SDIO | P0.09 | I2C0 SDA |
| 5 | 3V3 | 3V3 | 3V3 | 電源、ソフトで切替不可 |
| 6 | GND | GND | GND | 電源帰路 |

RESET未接続で使用します。ホストJP1の中央NCSを、GND側にもRE_B側にも接続しないでください。A2のR5はそのままで構いません。既にGND固定のホストを使う場合は固定を解除するか、A2側R5を外してMCLRへの経路を切り離します。**R5実装のままRESET_EXTをGNDに落とさないでください。**

A2のR4=10kΩとC7=100nFがMCLRに接続されます。reset-gpios省略時にドライバーは存在しないGPIOを操作せず、ソフトリセットを使います。

I2C0とSPI0は同じ0x40003000の周辺回路なのでSPI0は無効。I2C1も無効とし、100kHzで開始します。NFCピンのGPIO化は既存設定を維持。外付けプルアップがあるので内部プルアップを追加していません。

他の使用ピン：キー走査P0.03/P0.28/P0.29/P1.11/P1.15/P1.14、キー割り込みP1.13、エンコーダーP0.04/P0.05、電池ADC P0.02。A2との重複なし。単体XIAO例のD4/D5/D6は流用していません。

## ファイルの選び方

- 右通常評価版：`Corcell_R-iqs9151-A2-1mm-no-reset.uf2`
- 右初回診断版：`Corcell_R-iqs9151-A2-1mm-no-reset-diagnostics.uf2`
- 左：既存の `Corcell_L-dya-studio-xiao_ble_zmk.uf2`（PAW3222）。

両A2版とも初回評価用にタップ・押し続け・ピンチ・慣性を無効にし、まず1本指移動を確認します。通常版はログを抑える違いがあります。
右A2入力には軸交換・反転・倍率・自動レイヤーを足していません。既存の左PAW側の処理は維持しています。
A2の感度はDYA Studioの既存トラックボール設定と連動しません。`a2.conf`のドライバー設定で調整します。

## 診断ログ

診断版はUSB CDCをログ専用に使い、StudioのUSB UART transportを無効にしています。診断中はStudio USB接続を開かず、シリアル端末を1つだけ開きます。BLE Studio設定とキー動作は維持します。

1. 診断版を書き込み、USB接続。macOSなら `/dev/cu.usbmodem*`、Windowsなら対応するCOMポートを確認。
2. シリアル端末で115200 baudを指定してログを保存。起動ログは32KiBバッファと8秒の処理開始待ちで取得を補助しますが、遅く開くと取り逃す場合があります。
3. 必要なら端末の再接続を有効にしてリセットし、USB再列挙後に再接続。画面に何も出ない場合、他のアプリがポートを使用していないか確認。
4. 指を離して起動し、次を確認：
   - `Initializing TPS43 A2 13Rx/12Tx, resolution 3600x3300, reset software only`
   - `product number 0x09bc`
   - `ATI complete` / `Initialization complete`
5. 初期化成功後に1本指で中央と四隅をなぞり、`finger` / `f1x` / `f1y` / `rel x/y` と実際のカーソルを記録。

`RDY timeout` は配線・電源・RDY設定、製品番号不一致は接続先、`ATI calibration error` は電極・実装・オーバーレイ/設定を確認します。ログだけで部品不良と断定しません。

**版情報の制限**：指定ドライバーは製品IDをログ出力しますが、IC内のProduct Major/Minor Version・SHAの出力はありません。今回ドライバーを無断改変して追加していません。ログには本体コミット、ドライバーSHA、ビルド番号を併記してください。IC版の実測は未完了項目です。

## 段階的な実機試験

1. FFCの1～6番とRESET条件を確認。追加の配線変更を同時にしない。
2. USB給電でID・ATI・初期化を確認。
3. 1本指の中央・四隅、指離れ、無接触時の誤入力、取り付け方向を確認。
4. 通常評価版に戻してUSBと電池で比較。現在の本体にはセンサー接続時の電池起動不良が未解決なので、初回USB成功と電池起動成功を区別する。
5. 再起動、ホストだけのリセット、BLE再接続を確認。
6. 最後にディープスリープからキーで復帰させ、入力が戻るか確認。ドライバーにZMK PM suspend/resume callbackはなく、この統合は省電力の実機保証ではない。USB給電中は通常deep sleepへ入らない。
7. 通信と軸が確定してから、必要なタップ・スクロール等を1つずつ有効にする。

## 1mmオーバーレイ調整

13Rx×12Tx、Rx12→0、Tx45/43→33（44未使用）、全156交点、3600×3300は内蔵A2プロファイルで一致させます。これらは電極幾何情報で、感度の校正値ではありません。

`snippets/corcell-right-slot1-iqs9151-a2/a2.conf` に、ATI target=400、touch set/clear=30/26、ALP=8/8、filter bottom/top=30/511、bottom beta=20を明記。
試験ごとに「オーバーレイ材質・厚さ・接着材/厚さ・空隙・向き・給電方法・本体コミット・設定ファイル・結果ログ」を一緒に保存し、1項目ずつ変更します。

この構成にはAzoteq全レジスタ設定のエクスポート機能はありません。初期比較はa2.confとログを保存。周波数等まで調整する場合はメーカーGUIと対応する書込み/読出し環境で設定をエクスポートし、生成物を日付と実物条件とともに保存する必要があります。DYA StudioのエクスポートをA2の全レジスタ設定と扱わないでください。

## 再現ビルド

通常版（同じwest workspaceで `west update` / `west zephyr-export` 済み）：

```sh
west build -p -s zmk/app -b xiao_ble/nrf52840/zmk -d build-a2 \
  -S 'corcell-right-slot1-iqs9151-a2 studio-rpc-usb-uart' -- \
  -DSHIELD=corcell_r -DZMK_CONFIG=/absolute/zmk-config-Corcell/config \
  -DZMK_EXTRA_MODULES=/absolute/zmk-config-Corcell
```

診断版は `-S 'corcell-right-slot1-iqs9151-a2 zmk-usb-logging corcell-a2-diagnostics'` とし、別buildディレクトリを使います。GitHub Actionsはbuild.yamlの同名artifactsを参照。

## ソース照合

[指定ドライバー導入手順](https://github.com/yuchamichami/zmk-driver-iqs9151/blob/42fbda63f957a8f9f7e13fb2abfbdbde3d84fcf5/documents/tps43-a2.md)とソースを確認。I2Cアドレス0x56、RDY active-low、16bit little-endianレジスタ、STOP終了方式を[メーカー資料v1.1](https://www.azoteq.com/images/stories/pdf/IQS9150_IQS9151_datasheet.pdf)の§12と照合しました。
RDY待ち500ms、リセット後待ち100ms、ATI待ち1000msは指定ドライバーの実装値であり、新たな推測値ではありません。起動probe/soft-resetはforce communication、SHOW_RESET後は設定復元とATI再実行。復元失敗は次のRDYで再試行しますが、RDY自体が止まる状態の自動復帰は保証しません。
ドライバー側のQEMU各52件とXIAO確認は引き継ぎ実績であり、今回のCorcell統合で再実行した実機テストではありません。
